# HyperCube Server 2D Monitoring Dashboard Guide

이 문서는 `/admin/dashboard`용 문서가 아니라, 단일 서버 관제 페이지인 `/server-2d` 구현과 운영 기준을 정리한 문서다.

## 이 문서가 다루는 화면

- 대상 경로: `/server-2d`
- 목적: 전체 Agent 통합 관제가 아니라, 선택한 서버 1대의 상태를 한 화면에서 빠르게 파악하는 2D 관제 화면
- 핵심 초점:
  - 서버 자원 상태
  - 스택 상태
  - 전체 컨테이너 상태
  - 시간 범위별 추이

## 이 문서가 필요한 이유

기존 `admin-2d-monitoring-dashboard-guide.md`는 `/admin/dashboard`를 전제로 작성된 초안이었고, 현재 작업 대상인 `/server-2d`와 목적이 다르다.

즉:

- `/admin/dashboard`: 전체 서버/Agent 통합 관제
- `/server-2d`: 서버 1대 상세 관제

두 화면은 역할이 다르므로 문서도 분리해야 한다.

## 런타임에서 이 문서를 쓰는가

아니오.

이 문서는 앱이 직접 읽는 파일이 아니다. 개발자/디자이너/작업자 참고용 문서다.

즉 이 문서는:

- 화면 코드에서 import 하지 않음
- 라우팅에 연결되지 않음
- 브라우저에서 자동으로 보이지 않음
- 구현 기준과 작업 맥락을 남기기 위한 문서임

## 현재 `/server-2d` 기준 정리

현재 `/server-2d`는 아래 기준으로 관리한다.

### 1. 데이터 원칙

- 기존 3D 화면 데이터 재사용
- 단일 서버 기준 실시간 데이터 + 과거 추이 데이터 함께 사용
- 서버 메트릭과 컨테이너 메트릭을 같은 화면에서 본다

### 2. 시각화 원칙

- 스택 평균 추이는 지표별 그래프를 분리한다
  - CPU 평균
  - 메모리 평균
  - 트래픽 평균
- 각 그래프 안에는 모든 스택 평균선이 함께 들어간다
- 컨테이너별 선 수십 개를 한 그래프에 넣지 않는다

### 3. 대량 컨테이너 대응

- 컨테이너가 많아도 한 화면에서 상태 분포를 읽을 수 있어야 한다
- 일부 상위 컨테이너만 보여주는 방식보다, 스택 단위 집계 + 전체 상태 매트릭스가 우선이다
- 데모 서버와 실제 다량 서버 둘 다 기준으로 본다

### 4. 문서 분리 원칙

앞으로 `/admin/dashboard` 관련 문서는 관리자 통합 관제 문서로,
`/server-2d` 관련 문서는 단일 서버 관제 문서로 분리한다.
