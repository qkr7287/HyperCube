1. 배경과 목적

HyperCube 는 Docker 컨테이너 관리 + 모니터링 비중이 크지만, 실제 자산은 H100·A100 같은 GPU 를 사내 사용자에게 호스팅하는 것이 핵심. H100 은 MIG 슬라이스 단위로도, 전체로도 줄 수 있고 두 방식이 공존. 슬라이스/전체 할당이 어느 컨테이너에 붙어 누가 어떤 모델을 돌리는지를 한 화면에서 빠르게 파악하고 장애를 즉시 알아챌 운영자 대시보드.

/gpu-hosting 라우트 신설 + /server-2d 트리거. 1차 = mock 데이터, 실제 API 연결은 별도 작업.

4. 결정 사항 (v3)

  • 옵션 ② — "GPU 호스팅 플랫폼 + Docker 부가". /server-2d 그대로 + 새 라우트 /gpu-hosting.
  • 1차 = mock (백엔드 변경 0).
  • IA = Host group + GPU row + slice detail.
  • GPU 표현 = 행 리스트 (카드 그리드 X).
  • 행 클릭 = 인라인 expand. Detail 컨텐츠는 독립 컴포넌트 로 만들어 후속 panel 전환 가능.
  • 1차 지표 = GPU Compute.
  • 색 체계 = utilization quality ↔ incident severity 분리.
  • 기본 정렬 = Compute 내림차순, incident 있는 row 는 상단 sticky.
  • 아이콘 최소, 폰트 크게.
  • 1차 사용자 = Platform admin (admin-only).
  • 1차 action = Container detail navigate — 링크 target 은 /user/containers/[id]. mock 1차에서는 링크 렌더만, 클릭 시 toast "후속 단계 admin 접근 결정 후 활성" v3.1. 코드 확인 결과 MyContainerViewSet.get_queryset() 이 requester=user 필터라 admin 도 본인 컨테이너만 보임 → 후속 단계에서 (a) admin bypass / (b) 별도 admin route 중 결정.
  • 최소 viewport = 1440x900. 1280x720 에선 Temp 만 compact 유지 (Pwr 만 expand) v3.
  • 장애 source = Agent heartbeat + ResourceEvent + ContainerEvent v3 P0. OOM/DIE/HEALTH_STATUS 신호 누락 방지.
  • Live 기본 = 5s (1s opt-in).
  • Host offline precedence v3: HostMock.isOnline === false 이면 하위 모든 GPU 의 severity = 'offline' override. heartbeat stale 60s+ = warn, 180s+ = offline.
