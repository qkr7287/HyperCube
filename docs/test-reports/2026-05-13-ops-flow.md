## 5. Jupyter terminal WebSocket — Vite dev proxy 한계

### 5.1 증상
- JupyterLab UI 자체는 로드.
- File browser, Launcher 정상.
- Launcher → Terminal 클릭 시 새 탭은 열리지만 PTY 연결이 안 됨 (status bar `Terminal 0 0`).
- 브라우저 콘솔: `WebSocket /workspace/<wk>/terminals/websocket/<n>` 가 `readyState=0` 에서 timeout.

### 5.2 위치 분석 (좁히기)
```
$ ws://192.168.0.63:8000/workspace/<wk>/terminals/websocket/2     → state: open   (backend 직결 OK)
$ ws://192.168.0.63:3000/workspace/<wk>/terminals/websocket/2     → timeout       (Vite dev proxy 차단)
```
같은 path 의 HTTP 는 정상 (`POST /api/terminals` → 200, name=2 생성됨).

### 5.3 원인 (추정)
`frontend/vite.config.ts:31-35` 의 `/workspace: { ws: true }` 가 HTTP 는 forward 하지만, SvelteKit/Vite 의 catch-all dev middleware 가 WS upgrade 단계 직전에 `/workspace/...` 요청을 흡수해서 proxy 까지 도달 못 함. `/ws` prefix 는 동작 (현재 `/ws/server/...` 등 라이브 사용 중).

### 5.4 영향 범위
- **dev 전용**. Prod 는 `nginx/nginx.conf:36-` 에 `location /workspace/ { proxy_pass http://backend:8000/workspace/; }` 가 들어 있고 nginx 가 WS upgrade 도 처리하므로 영향 없음 (직전 검증 보고서에 prod-equivalent flow 가 그대로 PASS).
- dev 에서 UI 통한 Jupyter terminal 사용은 막힘. 검증 가능한 우회: (a) backend 8000 포트 직결, (b) `docker exec <container> nvidia-smi` 등 host-side.

### 5.5 권장 fix
- 옵션 A: Vite proxy entry 의 우선순위 / pathRewrite 변경.
- 옵션 B: dev 환경에서도 nginx 컨테이너를 띄워 `:80` 또는 `:443` 으로 정식 흐름 검증 (prod parity).
- 옵션 C: 별도 prefix (예: `/jupyter/<wk>/`) 로 라우팅 분리해 SvelteKit 의 catch-all 회피.

## 7. 영구화 / Follow-up

1. **(이미 반영)** `deploy/docker-compose.yml:73` 에 backend → `hc-ml-internal` external network 합류.
2. **(이번 세션)** `backend/apps/containers/workspace_proxy.py` — cookie-first 인증.
3. **(임시)** `docker network connect hc-ml-internal hc-backend` — dev 의 `docker-compose.dev.yml` 에도 동일 합류를 반영 (prod 와 parity).
4. **(미수정)** `serializers.py` — delete request 가 `target_container.agent_id` 에서 `target_agent` 자동 derive 하도록 보강. 현재는 클라이언트가 명시해야 함.
5. **(미수정)** Vite dev proxy `/workspace` WS forwarding — `/ws` 와 동일하게 동작하지 않음. 별도 prefix 분리 또는 dev 환경에 nginx 추가 검토.
6. **(미수정)** backend force-recreate 후 agent stale WS — backend health probe 에 따른 agent WS reconnect 가속 또는 backend 가 agent 채널을 잃었을 때 명시적 reset.
