# Claude Code Prompt For `/server-2d`

아래 프롬프트를 그대로 Claude Code에 전달하면 된다.

```text
HyperCube repo에서 `/server-2d` 단일 서버 2D 관제 페이지를 완성해줘.

가장 중요한 제약부터 말할게.

1. `/admin/dashboard`는 절대 건드리지 마.
2. 사용자가 `/admin/dashboard`를 현재 직접 다시 작업 중이니, 관련 파일 수정 금지.
3. 작업 대상은 오직 `/server-2d`.

이 페이지의 목적은 전체 서버 통합 관제가 아니라, 서버 1대를 2D로 깊게 보는 모니터링 시스템이야.
기존 3D 페이지 데이터를 최대한 재활용해야 하고, 데이터가 줄어들면 안 돼.

핵심 목표:
- 이 페이지 하나만 띄워도 해당 서버의 현황을 한눈에 파악 가능해야 함
- 가장 중요한 것은 서버 자원 상태와 각 컨테이너 상태
- 아래로 길게 스크롤하는 구조보다, 핵심 현황이 첫 화면에서 빠르게 읽혀야 함

반드시 반영할 요구사항:

[기본 UI/UX]
- 기능명/텍스트는 전부 한국어
- 각 주요 카드/차트/패널마다 `?` 툴팁 필요
- 툴팁은 비전공자도 이해 가능한 수준으로 짧고 명확하게 작성

[서버 전환]
- 서버를 바꾸면 실제 데이터 소스가 확실히 바뀌어야 함
- 이전 서버 데이터가 남으면 안 됨
- 실시간/과거 데이터/차트/컨테이너 목록이 모두 서버 기준으로 동기화돼야 함

[더미 서버]
- 데이터가 많은 데모 서버 하나를 제공해줘
- 스택 여러 개
- 컨테이너 수 충분히 많게
- running / paused / restarting / exited / problem 상태 섞기
- 네트워크/볼륨/지표 변동까지 보이게

[차트]
- 스택은 컨테이너 그룹이므로 컨테이너별 선이 아니라 스택 평균 선이어야 함
- 지표별로 그래프를 분리해줘
  - CPU 그래프 1개: 모든 스택 평균선 포함
  - 메모리 그래프 1개: 모든 스택 평균선 포함
  - GPU 그래프 1개: 가능하면 모든 스택 평균선 포함
  - 네트워크 그래프 1개: 가능하면 모든 스택 평균선 포함
- 한 그래프 안에 모든 스택이 legend로 구분되어야 함
- Chart.js 사용

[산점도]
- 라이브러리 기반으로 구성
- 운영자가 CPU/메모리 분포를 읽기 쉽게

[프레임 다이어그램]
- 현재처럼 약한 도식 말고, 봤을 때 프레임 다이어그램으로 인지되는 구조형 시각화로 개선
- 라이브러리 사용 가능
- 스택과 컨테이너 관계를 명확히 보여줘

[열지도]
- 상위 몇 개만 잘라서 보여주는 방식은 부족함
- 많은 컨테이너에서도 읽히는 구조로 다시 설계
- 스택별/그룹별로 모든 컨테이너를 읽기 쉽게 보여주는 방향 선호
- 데모 서버에서도 보기 쉬워야 함

[대량 컨테이너 대응]
- 실제 16번 서버처럼 컨테이너가 많아도 UI가 깨지면 안 됨
- 반드시 브라우저로 16번 서버를 확인하고 조정해줘

[시간 범위]
화면에서 범위 선택 가능하게 하고 아래 규칙을 따라줘.

- 1m: polling 10초 / bucket 5초 / 30 points / 약 2분 30초 / backend는 5m 요청 후 최근분 필터
- 5m: polling 30초 / bucket 15초 / 60 points / 과거 15분 / backend 5m
- 1h: polling 1분 / bucket 60초 / 240 points / 과거 4시간 / backend 1h
- 24h: polling 5분 / bucket 5분 / 500 points / 약 41시간 / backend 24h
- 7d: polling 30분 / bucket 30분 / 600 points / 약 12.5일 / backend 24h fallback

[중요]
- GPU 스택 평균 그래프를 정확히 만들 수 있는 데이터가 없으면 추정으로 속이지 말고, 어떤 백엔드 데이터가 부족한지 정확히 보고해줘

[검증]
- `/server-2d` 실제 페이지를 브라우저에서 확인
- 로그인 후 실제 서버 전환 확인
- 16번 서버 확인
- 데모 서버 확인
- 대량 컨테이너에서도 레이아웃/열지도/프레임 다이어그램/전체 컨테이너 패널이 읽히는지 확인

최종 보고에는 아래를 포함해줘:
- 어떤 파일을 수정했는지
- `/admin/dashboard`는 건드리지 않았다는 점
- 실제로 해결된 것
- 아직 데이터 한계로 못한 것
```
